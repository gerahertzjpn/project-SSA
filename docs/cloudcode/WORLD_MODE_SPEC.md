> (энтропия). Изменены: world/season/offseason/manager/training_ops/feature_flags.
> Это решение ЗАМЕНЯЕТ разделение ролей из §0.6 и старую оценку токенов §10.

### Уровни участия ЛЛМ (главная ось дизайна)
- **L0 — механика** (формула, как сейчас): 0 вызовов, $0, но все клубы одинаковые.
- **L1 — ЛЛМ задаёт политику, код исполняет** (1 вызов на фазу → приоритеты/правила):
  мало вызовов, копейки, у клубов есть характер; решения приняты заранее. **Дефолт.**
- **L2 — ЛЛМ в цикле** (1 вызов на пик/ставку/оффер): живо и реактивно, дороже и
  медленнее. Применяем точечно.

Фолбэк: КАЖДОЕ ЛЛМ-решение страхуется эвристикой; эвристики НЕ удаляем — они
становятся фолбэк-слоем. При срабатывании фолбэка — **обязательное уведомление**.

### Решения по подсистемам (зафиксировано владельцем)
- **Драфт — L2 (по-пику, живой).** Переиспользуем паттерн `src/regionals/draft.py`
  (снейк, structured output, `_auto_pick` фолбэк). 22×3 = 66 пиков разово в бутстрапе.
  - **Season 0: все равны, «слабый драфтит первым» НЕ действует** (порядок снейка
    равный/случайный). Правило «слабейший первым» включается с **Season 1**, когда
    появляются новички. (Сейчас `balanced_draft` всегда сортирует по слабейшему — правим.)
- **Аукцион тренировок — L1 по умолчанию.** Легенда: менеджер шлёт помощника с планом,
  код исполняет. Число слотов задаёт владелец. 🔴 Опционально: **живые торги L2**
  (можно смотреть) — помечены КРАСНЫМ, требуют отдельного подтверждения + явного
  нажатия «ДА» + предупреждения «займёт кучу времени и денег». Всегда второстепенно.
- **Трансферный рынок — L1.** Несколько претендентов → продаётся **тому, кто
  предложил больше** (highest bidder).
- **Трата сертификатов** — внутри того же вызова «план рынка/окна» (без отдельных вызовов).
- **Плейбук** (бывшая работа тренера) — **1 вызов/команда перед турниром**: база-
  стратегия + состав + замены IF-THEN («у соперника робот на защите → 2 людей на
  раш»). Код сверяет условия по матчам и исполняет — **вызовов на матч нет**. В
  бутстрапе плейбук не нужен (матчи там механические по рейтингам).

### Лента межсезонных событий
Пошаговая хроника межсезонья (механическая, с небольшим интервалом вывода): кто что
запрашивает/принимает/покупает/тренит. Пример: «менеджер X хочет купить A5 →
менеджер Y хочет купить A5 → владелец A5 продал Y».

### История решений ЛЛМ
Решения ЛЛМ сохраняются на диск **только как ИСТОРИЯ** (хроника), НЕ для
воспроизведения. Турниры не должны повторяться — сиды всегда разные (см. §0-ter).

### Стоимость (новый батч-дизайн; заменяет §10)
- Бутстрап: ~66 драфт-вызовов разово → **~$0.3** (Opus).
- Живой сезон: 22 команды × ~2 L1-вызова (рынок + плейбук) ≈ 44 → **~$3.5/сезон** (Opus).
- Прогон 3 сезона: **~$11** (Opus) / ~$6.5 (Sonnet) / ~$2 (Haiku). Цена — не фактор.
- Модель переключается через env (как `REGIONALS_LLM_MODEL`) для A/B по качеству.

## 0-ter. ГЕНЕРАЦИЯ СЛУЧАЙНОСТИ (2026-06-17): энтропия на симуляции (объём A)

Цель: **каждый прогон уникален, турниры не повторяются**; убрать паттерн «base+1».
Объём — **A (только симуляция мира)**, подтверждён владельцем.
✅ **РЕАЛИЗОВАНО**: `src/core/rng.py` (`fresh_seed`/`resolve_seed`/`make_rng`/`Spawner`).
Энтропия + запись сида: `world['seed']` (new_world), `world['bootstrap']['seed']`,
`summary['seed']` (сезон), `report['seed']` (межсезонье). Проверено: два прогона
seed=None дают разных чемпионов; явный сид — воспроизводим; тесты зелёные. Прим.:
режимы `regionals`/`league` и движок матчей (`runner.py`) — отдельные системы, их
base+offset НЕ трогался (вне объёма A; можно расширить по запросу).

- **Энтропия на входе прогона.** Публичные точки входа (`new_world`, `bootstrap_world`,
  `run_regular_season`, `run_offseason`, `run_match` для живого матча, `simulate_soloq`,
  `make_play_fn`) по умолчанию `seed=None` → берём свежий сид из ОС-энтропии
  (`secrets.randbits(64)`) ОДИН раз, **записываем в метаданные прогона/мира** (история),
  прокидываем вниз. Тесты передают явный сид → детерминизм, ничего не падает.
- **Убрать base+offset в симуляции:** вместо `seed+index` / `seed*10+index` — один
  прошитый генератор, дочерние независимые потоки через `SeedSequence.spawn()`.
  Точки: `season.py:55`, `league.py:171/273`, `regionals.py:223/240`, `runner.py:100`.
- **Новые нейронки (рекруты/форки в live-мире):** сид из энтропии прогона, **но
  записывается** (уникальность сохраняется, как у базы-18).
- **НЕ трогаем (контролируемое by design, под защитой CLAUDE.md):** идентичность
  базы-18 (`population.py`, `genotype_hash` включает seed), воспроизводимость
  тренировочных прогонов (`ppo/team_ppo/population` worker/episode сиды), характер
  менеджера (`manager.py:56` `crc32(franchise_id)` — стабилен намеренно).
- **Хелпер** `src/core/rng.py`: `fresh_seed()`, `make_rng(seed)`, `spawn(rng, n)`,
  запись сида в историю.

Итог: реальные прогоны всегда разные; нейронки уникальны и воспроизводимы из записи;
~90 seed-тестов остаются зелёными (передают явные сиды).

## 0-quater. ОБОСНОВАНИЕ КОЛОВ + ПОЗИЦИИ (2026-06-17): A/B/C/D реализованы

> ✅ Чтобы коллы менеджера были основаны на ДАННЫХ, а не на хардкоде. Модули:
> `src/world/scouting.py` (новый), правки `playbook.py`/`calendar.py`/`world.py`/
> `llm_manager.py`/`season.py`. Тестов на слой: ~30. См. также §0-bis.

- **Позиции (A1/A2/A3).** У игрока `position_affinity` (латентный множитель силы по
  позициям — играть на своей позиции выгоднее) и `position_stats` (НАблюдаемый
  winrate по позициям, копится по официальным матчам). Менеджер/ЛЛМ **расставляет
  игроков по позициям и делает условные ЗАМЕНЫ** (в т.ч. со скамейки при 4+). Сила
  матча = позиционная сила состава + контр-стратегия + исполнение. Разные игроки —
  разный winrate на разных позициях, и это влияет на исход.
- **A — запись колов.** `calendar.record_series` сохраняет, какую стратегию звала
  каждая сторона (`home_strategy`/`away_strategy`) → есть история «кто что звал и чем
  кончилось». В Season 0 позиции НЕ копятся (только SoloQ).
- **B — разведка (intel).** `scouting.intel_report` собирает из истории: свои прошлые
  коллы+winrate, мету лиги (winrate по стратегиям), winrate по позициям, H2H против
  соперников, измеренную матрицу контр. `render_intel` кладёт это В ПРОМПТ менеджера —
  коллы становятся обоснованными («раш бил роботов 7-2», а не «по примеру»).
- **C — измеренная матрица контр.** `playbook.counter_points` берёт winrate стратегии
  vs стратегии из сыгранных матчей со **сжатием к дизайн-приору** (`PRIOR_WEIGHT=25`):
  при 0 играх = текущий дизайн, с ростом данных → реальные числа. **Включена всегда**
  (флаг не нужен — сжатие безопасно). Объём данных: общие пары достигают полезного
  сигнала за ~2-3 сезона (ячейка ~25-50 игр = полу/полное доверие), вся матрица
  «созревает» за ~6-10 сезонов; редкие пары дольше остаются на приоре (это норм).
- **D — подготовка под соперника (взаимная).** Условия `opp_last_strategy`, `vs_team`
  (+ `opp_faction_majority`/`opp_strategy`). Оба плейбука резолвятся ДРУГ ПРОТИВ ДРУГА
  одновременно → команда готовится к тебе, ты к ней; замена/смена позиции — часть
  ответа. Контекст соперника несёт его ПОСЛЕДНИЙ реальный колл (`last_strategy`).

## 1. Лиги и структура

- **Нижняя лига**: 2 группы (A, Z) по 6 команд = 12. Раунд-робин Bo3.
- **Верхняя лига**: 1 группа из 10 команд. Раунд-робин Bo3.
- Все матчи лиг — **Bo3**, все матчи плей-офф — **Bo5**.

### Плей-офф нижней лиги (Bo5), повышение 2 команд
- Верхняя сетка (UB): A1 vs Z1. Победитель → ГРАНД-ФИНАЛ; проигравший → финал нижней сетки.
- Нижняя сетка (LB): A2 vs Z3 и Z2 vs A3 → победители играют между собой →
  победитель играет финал нижней сетки против проигравшего UB → победитель → ГРАНД-ФИНАЛ.
- **Гранд-финал**: оба финалиста **повышаются** в верхнюю лигу. Победитель получает призовые плей-офф.

### Плей-офф верхней лиги (Bo5) — ВРЕМЕННАЯ ЗАГЛУШКА
- 9 и 10 места **вылетают** (9 → группа A, 10 → группа Z нижней лиги).
- UB: 1 vs 2 → победитель в гранд-финал, проигравший в финал нижней сетки.
- LB: 3 vs 4 → победитель в финал нижней сетки → победитель → гранд-финал.
- Гранд-финал: чемпион (призовые плей-офф). (Будет расширено позже.)

Повышение 2 / вылет 2 → верхняя всегда 10, нижняя всегда 12 (баланс потоков).

## 2. Командное Elo

- Шахматное Elo (переиспользуем `regionals/elo.py`, K=32), старт 1000.
- Считается ТОЛЬКО по официальным встречам (лига + плей-офф).
- **Влияет счёт встречи**: `delta = K * margin_factor * (actual − expected)`,
  где `margin_factor = |won−lost| / win_threshold` (Bo3: 2-0→1.0, 2-1→0.5;
  Bo5: 3-0→1.0, 3-1→0.67, 3-2→0.33). Сухая победа двигает сильнее тесной.

## 3. SoloQ (рейтинг игроков)

- Рейтинг игрока теперь **не** зависит от побед/поражений команды — только SoloQ.
- 10 раундов. Каждый раунд: игроки распределяются по **бандам шага 100**
  (банд = floor(rating/100)*100); 900-1000 не играет с 1000-1100.
- Внутри банда формируются случайные команды 3v3, но **средний рейтинг команд в матче
  выравнивается** по возможности (жадная балансировка). Матчи **Bo1**.
- Если игроку не нашлось комнаты (в банде <6 игроков / остаток) — **пропуск раунда**.
- Изменение рейтинга: базовый Elo-дельта по средним рейтингам команд, импакт меняет
  до **±60%** («до 60% от очков за победу»). Старт 1000.
- При инициализации мира SoloQ проводится для посева рейтингов; **только SoloQ
  сохраняется** между этапами Season 0.

## 5. Экономика (ОТБАЛАНСИРОВАНО, числа в `economy.py`, параметризовано)

Валюта — условные кредиты (k¥). Все числа в одном конфиге, легко тюнить.

**Призовые за место (команде, не игрокам):**
- Верхняя лига (1→10): 1000, 800, 650, 520, 420, 340, 280, 230, 190, 160.
- Нижняя лига (1→12): 450, 380, 320, 270, 230, 195, 165, 140, 120, 100, 85, 70.

**Призовые плей-офф — только победителю ГРАНД-ФИНАЛА:**
- Верхняя: +800. Нижняя: +500.

**ЗП игрока (каждый сезон, всем в составе, даже не игравшим):**
- Целевая ЗП `target = base * value`, где value от soloq_rating (доминанта),
  атрибутов (крутость) и недавней результативности. base≈50.
- **Плавность:** EWMA `salary ← salary + α*(target − salary)`, `α=0.25`.
  → один плохой сезон роняет ЗП лишь на ~25% разрыва («не сильно»); 3 плохих
  сезона ≈ −58% («сильно»). Топ-игрок остаётся дорогим даже в нижней лиге.
- Новичкам ЗП начисляется только **после первого сыгранного сезона**.

**Баланс/анти-снежный ком:** победы поднимают soloq/результативность игроков →
их ЗП растёт → срезает профицит чемпиона. Это естественная отрицательная обратная
связь против снежного кома (а не жёсткий cap).

**Seed-казна** на старте Season 1: верх 600 / низ 400 (❓ тюнинг). Во время Season 0
денег нет и ЗП не платится. Порядок расчётов в сезоне: сыграли → призовые →
ЗП → трансферы → аукцион тренировок.

## 6. Трансферное окно (2 раунда)

- Менеджеры покупают свободных агентов (у игрока min-цена; если желающих >1 —
  **аукцион**). Можно покупать/продавать игроков у любых команд.
- **Лимит: ≤3 запроса суммарно на команду за окно.** 2 раунда; в один раунд нельзя
  2 запроса на одного игрока, но можно 3 запроса разным игрокам/командам.
  2 раунда → можно 2 запроса на одного игрока с разными условиями.
- Команда может выставить игрока на трансфер **сразу на 2 раунда** (нельзя на 1),
  чтобы другие видели, кого вероятно купить.
- **Новички**: бесплатны (но требуют ЗП), команды ВЕРХНЕЙ лиги их брать НЕ могут;
  в нижней — драфт «сначала слабые, потом сильные» (по желанию, можно никого).
- Реализм: никаких «топ-игрок за 1 иену» — оценка по value игрока (см. §5); запросы
  ниже разумного порога отклоняются. (LLM-решения — заглушка-эвристика, §0.)

## 7. Аукцион тренировок — БЕТА (gradeslot-сертификаты; исполнение = заглушка)

Владелец между сезонами задаёт **размер gradeslot в ШАГАХ** (`steps_per_slot`,
дефолт 1 млн) и число слотов; показываем расчётное время прогона слота (ETA).
N слотов разыгрываются по одному на аукционе; команды ставят по желанию; LLM видит,
кто сколько взял/предложил (`public_state`). Победитель получает **сертификат** на
эти шаги. Поскольку размер слота меняется между сезонами, ценность считается в
**шагах, а не в числе слотов** — команда может: **банковать** (отложить),
**комбинировать** несколько сертификатов (напр. до ≥ 4 млн шагов для форка) или
**потратить** на тренировку. Типы трат: `skill_up` / `teamplay` / `meta_adapt`
(любой бюджет) и `create_player` (форк, ≥ `FORK_MIN_STEPS` = 4 млн суммарно).
Реальное исполнение — выбор меню в **WORLD_TRAINING_OPTIONS.md** (см. §9).

## 8. Инициализация нового world + Season 0 (❓ моя интерпретация)

Правила: игроки/команды/бюджеты — с чистого листа; общий ресурс — только пул
нейронок (нет может появиться в другом world под другим именем). Во время
инициализации: денег нет, ЗП нет, история матчей НЕ сохраняется, сохраняется
**только SoloQ**. Команды драфтят сбалансированно до 3 игроков.

Порядок при создании world:
1. Создать пул игроков (разнообразных) и 22 команды (из franchises).
2. **SoloQ** (10 раундов) → посев рейтингов (сохраняется).
3. **Сбалансированный snake-draft** до 3 игроков на команду.
4. **Season 0 (бутстрап)** — серия сезонов нижней лиги:
   - 12 команд в нижней лиге, 10 — в очереди-резерве.
   - Каждый прогон: сыграть нижнюю лигу → 2 гранд-финалиста **поднять** в верхнюю →
     2 освободившихся слота добрать из резерва.
   - Повторять, пока верхняя не наберёт 10 (≈5 прогонов; резерв исчерпан).
   - **+3 прогона** нижней лиги после заполнения (без повышений) для «прогрева».
   - Денег/ЗП/истории нет; SoloQ сохраняется.
5. Дальше — Season 1 по полным правилам (деньги, ЗП, трансферы, тренировки, история).

> ✅ ПОДТВЕРЖДЕНО владельцем: 12 в лиге + 10 резерв; при повышении 2 — добор 2 из
> резерва; продолжать, пока все 22 не задействованы; затем +3 прогона. Реализовано.

## 10. Оценка расхода токенов (LLM) и оптимизация

LLM-вызовы только там, где есть РЕШЕНИЯ менеджера. Один вызов ≈ системка(персона)
+ компактная ситуация ≈ 700–1200 in / 120–250 out токенов.

На один сезон world (22 команды):
- Планы на матч (менеджер на встречу, не на карту): лиги ~ (15+15+45) встреч/сезон
  ≈ 75 встреч × 2 команды, но план кэшируем на встречу → ~150 вызовов.
- Трансферы: 2 раунда × 22 × ≤3 запроса → ≤132 решения, реально ~60–90.
- Аукцион тренировок: N тренировок × участники-заявки → ~N×10 микро-решений.
- Драфт новичков/окно: ~22–44.
Итого ~300–450 вызовов/сезон. На Opus (5/25 $/1M): ≈ 450×(1.0k in+0.2k out) ≈
0.45M in + 0.09M out ≈ $2.25 + $2.25 ≈ **~$4.5/сезон** на Opus.

Оптимизации (заложено в дизайн):
- Персона-дефолт-план без LLM (бесплатно) — фолбэк уже есть.
- Один план на встречу (Bo3/Bo5), не на карту (÷ число карт).
- Только «команда-в-фокусе» зовёт LLM, остальным — дефолт (÷2).
- Компактные карточки (`compact_card_line`) и краткие ситуации (token-lean).
- Haiku вместо Opus на рутине (÷5).
- Будущее: нейро-менеджеры (см. LLM_MANAGER_ORDERS_SPEC §БУДУЩЕЕ) → $0 на планах,
  LLM только на комментарии.
→ С дефолт-планами + Haiku реальный сезон сводится к **центам–$1**.
