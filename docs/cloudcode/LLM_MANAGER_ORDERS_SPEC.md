# LLM_MANAGER_ORDERS_SPEC.md — приказы менеджера и obedience сетей

Статус: ДИЗАЙН (вход для ретрена с нуля). Дата: 2026-06-16.
Связано: ADR-0003 (core_progress shaping), [[project_population18]], регионалс.

## Принципы (требования пользователя)

1. **Win-first.** Сеть ВСЕГДА стремится победить. Приказ задаёт *как* (стиль/роль),
   а не *что* (цель всегда — выигрыш). Самоубийственный приказ не исполняется до
   проигрыша: награда за победу доминирует.
2. **Приказ реально влияет.** Канал приказа вшит в наблюдение и в награду →
   поведение сети меняется соответственно приказу. Эффективность РАЗНАЯ (зависит
   от obedience сети и от того, насколько приказ win-совместим в ситуации), но
   влияние ненулевое и проверяемо.
3. **Послушание — это характер сети** (obedience), часть генотипа. Кто-то лоялист,
   кто-то маверик.
4. **Менеджеры (LLM) принимают реально умные решения** — приказ обоснован
   состоянием игры; качество плана = насколько приказ повышает winrate.
5. **Есть личные приказы** (per-position): один идёт в тех, другой пушит и т.д.

## Структура приказа (что выдаёт LLM-менеджер на матч)

Менеджер задаёт ОДИН план на матч: командный слой + личная роль каждой из 3 позиций.

### Слой A — командный план (на всю тройку)

**`tempo` — интенсивность/риск (4):**
| знач | смысл | per-tick alignment-сигнал A |
|---|---|---|
| `turtle` | беречь ядро/армию, держать узлы, бой у дома на выгоде | +удержание core_hp и узлов, −оверэкстенд/потери |
| `balanced` | нейтраль (якорь) | A ≈ 0 (только базовая награда) |
| `aggressive` | проактивно навязывать бой, лезть вперёд | +урон по чужому ядру, +захваты вперёд, +engage |
| `all_in` | всё на быстрый снос, принять риск | сильный +урон по ядру, ослабить штраф своего риска, +скорость |

**`win_path` — путь к победе (4):**
| знач | смысл | A |
|---|---|---|
| `economy` | контроль CP, доход, длинная игра | +узлы, +ресурсный перевес, +эко-здания |
| `core_rush` | закоммититься на снос вражеского ядра | амплификация core_progress по слабейшему врагу, +подвод армии |
| `baron_lord` | приоритет Baron→Лорд | +урон/килл Baron, +эскорт/приземление Лорда |
| `outlast` | держать и пережить (тай-брейк по core_hp/камбэк) | +свой core_hp к концу, +выживание |

### Слой B — личная роль позиции (per-net, «личный приказ») (5)

**`role`:**
| знач | смысл | A |
|---|---|---|
| `carry_push` | вести агрессию, давить приоритетное вражеское ядро | +урон вперёд, +присутствие у целевого ядра |
| `anchor_defend` | держать дом/своё ядро, костяк обороны | +нахождение у своего ядра, +отражение штурма |
| `tech_eco` | идти в тех/экономику, скейл на лейт | +тех/эко-здания, +экономика |
| `roam_objective` | Baron/Лорд, роуминг между лейнами | +участие в Baron/Лорд, +мобильность по лейнам |
| `support_flex` | усиливать там, где идёт бой | +подкрепление активных боёв |

LLM может раздать 3 позициям разные роли (один `tech_eco`, двое `carry_push` и т.п.).

## Послушание — ЗАПЕЧЁННАЯ черта весов, НЕ obs-параметр

**РЕШЕНИЕ (важно):** отдельного obs-скаляра obedience НЕТ. Послушание задаётся
**весом order-shaping в рецепте КАЖДОЙ сети** (`order_shaping_weight`) во время её
обучения. У кого вес выше — та сильнее слушается (поведение запечено в веса),
у кого ноль — маверик. Это буквально «обучи одну слушать, другую — нет».

Почему так лучше, чем obs-скаляр:
- аутентичный **характер** (свойство весов), а не рантайм-ручка;
- **obs проще** (канал = только tempo/win_path/role);
- нет RL-риска «прочитает ли сеть скаляр obedience»;
- ложится в population-18: `order_shaping_weight` = ещё один knob рецепта/генотипа
  (как lr/entropy) → бесплатно, **эволюционируемо** (наследуется/мутирует в
  lineage), **без culling**.

Анти-сегрегация: order-shaping **мал и win-нейтрален** → разный
`order_shaping_weight` меняет СТИЛЬ, а не winrate → не лестница силы, отбор не
загоняет популяцию в один архетип.

- **v1:** единый `order_shaping_weight` для всех (uniform) — канал доказываем на
  равных.
- **Tier-2:** per-net `order_shaping_weight` как ось разнообразия (архетипы:
  defiant 0.0 · independent · balanced · loyal · zealot — последний исполняет, но
  не до проигрыша).

Абляция (go/no-go) → **кросс-сетевая:** сеть с высоким весом vs с низким под
одним приказом → у первой распределение действий сдвигается сильнее.

## Менеджер (LLM) — граундинг, персона, эволюция

- **Граундинг (обязателен для «умных» решений):** на вход даём карточки ростера
  (per-net статы из population_balance), фракционные приоры, вероятный состав
  соперника, счёт серии, итоги прошлых игр. Мусор на входе = мусор на выходе —
  качество приказа = качество контекста.
- **Персона = непрерывные уклоны** (агрессия/риск/эко/верность плану), НЕ жёсткий
  скрипт. Хардкод-директива «всегда играй на победу». Стартует нейтральным,
  характер разгоняется за сезон → «плавно».
- **Защита от «менеджер топит команду»:** order-shaping мал и win-нейтрален →
  плохой план стоит маржинального winrate, не смертельной спирали (пол держит
  win-first). Сети игнорят приказ, ведущий к проигрышу.
- **Эволюция:** LLM по весам не эволюционирует. v1 — адаптация В КОНТЕКСТЕ (даём
  его W/L и что сработало). Tier-2 — параметризовать персону уклонами и отбирать
  по результатам сезона (мета-эволюция менеджеров).
- **«Выкинуть всех и начать заново»:** это сезонный ростер-менеджмент / ре-драфт
  (драфт уже LLM-управляем), отдельно от приказа-на-матч. Tier-2.

## Наградная архитектура (win-first, проверяемо)

```
R = R_terminal(±1, ДОМИНИРУЕТ)
  + shaping_weight * Δ team_score                  # существующее (вкл. core_progress)
  + order_shaping_weight(net) * ΔΦ_order           # НОВОЕ, per-net = «послушание»
```

- `Φ_order` — потенциал, накапливающий per-tick alignment A по активным рычагам
  (командным + личной роли). Терм **потенциальный/телескопирующий** (как
  core_progress) → в пределе НЕ меняет оптимальную политику, только уплотняет
  сигнал «играй в стиле приказа».
- `order_shaping_weight(net)` — МАЛЫЙ (порядок core_progress) и **per-net = это и
  есть послушание** (в v1 одинаков для всех; в Tier-2 разный по рецепту). Так что
  суммарный order-shaping ≪ терминала. Следствия:
  - в **win-неоднозначных** ситуациях (линии равны по EV победы) shaping склоняет
    сеть к приказу → влияние реально;
  - в **win-критичных** ситуациях доминирует победа → сеть отклоняется от плохого
    приказа. = «слушается менеджера, но стремится победить»;
  - сеть с весом 0 (`defiant`) учится максимизировать только победу (канал ≈ шум),
    с высоким весом (`zealot`) — жёстко условиться на приказ.
- «Умный менеджер»: хороший приказ = win-совместимая линия → следование поднимает
  winrate (высокий вес помогает). Плохой приказ воюет с победой → высокий вес
  вредит. Интеллект менеджера и реальность влияния возникают естественно.

## Кодировка obs (Tier 1 = командный слой + роль)

- `tempo`(4) + `win_path`(4) + `role`(5) one-hot = **+13 float**. Послушание в obs
  НЕ кодируется (это вес награды, см. выше).
- Меняет `OBSERVATION_DIM` (5188→5201) → бамп `OBSERVATION_VERSION`
  (`train_obs_v3.1` → `train_obs_v4_orders`) → старые чекпойнты несовместимы →
  **обучение С НУЛЯ** (принято).

## Тренировка

- Канал приказа **сэмплится дёшево** каждый эпизод (случайные/скриптовые планы),
  LLM в цикле обучения НЕ зовётся → стоимость LLM при тренировке = $0.
- `order_shaping_weight` — per-net knob рецепта (часть генотипа); v1 uniform.
- LLM-менеджер подключается только на **showcase** (регионалс): ~1 умное решение
  на матч. Для «реально умных» планов — Opus 4.8 (≈$0.015/матч; копейки), Haiku —
  опционально для дешёвого объёма.

## Acceptance / go-no-go (ДО showcase)

1. **Проводка** (без обучения): obs-dim сходится, env прокидывает приказ,
   forward/маска/decode не падают. ✅ (Tier-1 obs-канал)
2. **Канал живой** (после ретрена): кросс-сетевая абляция — одно состояние, один
   приказ, сеть с высоким `order_shaping_weight` vs с низким → у первой
   распределение действий сдвигается сильнее. KL≈0 у всех = канал мёртв, чинить.
3. **Влияние полезно**: при «умном» приказе winrate высоко-послушной сети
   ≥ baseline; при «глупом» — ниже. Подтверждает п.2 + win-first.

## БУДУЩЕЕ НАПРАВЛЕНИЕ (отложено) — нейросетевые менеджеры + дешёвый скейл

Зафиксировано 2026-06-16 как возможный путь развития (НЕ реализовано).

**Мотив:** прогон мега-турнира (16 стран + ЧМ, ~800-1000 игр) на Opus-планах
каждый матч ≈ $25-35 LLM. Для частых прогонов дорого.

**Факты по железу/скейлу (замерено):**
- GPU уже используется (RTX 4070 SUPER, device=auto→cuda). Узкое место —
  CPU-симуляция движка/obs (чистый Python), а не GPU. Ускорение тренировки =
  больше CPU-воркеров, не более жирный GPU.
- Один матч на нейронках ~1.4 c (1 ядро). Мега-турнир ~800-1000 игр →
  ~5 мин на 8 ядрах. Компьют дешёвый; дорога только разовая тренировка сетей.
- 90 команд — тривиально (данные/персоны/лого). 300 игроков — узкое место:
  от нуля ~1-2 млрд шагов (~3-6 недель 1 машина); умнее — ~30-50 базовых сетей +
  ~250 lineage-веток (пертурбация+дотрен) → дни.

**Путь «нейро-менеджеры» (снимает поматчевую цену LLM навсегда):**
1. Менеджер-сеть: вход = ситуация (статы своего ростера, состав соперника,
   фракционный матчап, счёт серии, прошлые результаты) + вектор персоны; выход =
   план в нашем словаре (tempo/win_path/3×role). Одна сеть на все 90 персон через
   персона-вход (или мелкие головы).
2. **Имитация Opus** (разово ~$30-60 на датасет «ситуация→план») → характерные
   вменяемые колы из коробки. НО: заморожена, потолок = качество Opus (разумные
   эвристики, не оптимум).
3. **RL на winrate команды** (без LLM) → превосходит Opus, учит реальный мета,
   продолжает расти. Это и есть «эволюция».
4. **Сезонный отбор персон** (опц.) → менеджеры расходятся характерами.
5. LLM остаётся ТОЛЬКО на комментарии (Haiku, центы).

«Живость» = персона (есть) + ManagerMemory-адаптация (есть) + RL/эволюция (TODO).
Чистая имитация = умный, но статичный клон Opus; имитация+RL = растущий менеджер,
способный перерасти учителя.

Цена мега-турнира после этого: ~$0.5-2 (только Haiku-комментарии) + ~5 мин компьют.

**Промежуточные дешёвые шаги (без нейро-менеджеров):** Haiku вместо Opus на планы
(÷5); план на встречу, не на игру (÷2-3); только команда-в-фокусе зовёт LLM (÷2);
бесплатные дефолт-планы по персоне (уже есть) → $0 на планах.
