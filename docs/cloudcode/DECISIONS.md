# ADR-0001: Population-18 free-agent draft pool через frozen-snapshot self-play

Дата: 2026-06-09
Статус: принято (подготовлено к запуску; обучение ещё не проводилось)

Контекст: нужно подготовить тренировку 18 уникальных нейросетей — «1 сид = 1
игрок», по 6 на каждую из 3 фракций. Каждая сеть должна играть на любой позиции
с любым союзником, быть максимально уникальной; ключевая механика — self-play;
отбор/culling сейчас запрещён. Существующий командный тренер обучал фиксированное
трио {A1,A2,A3} только за фракцию humans.

Пользовательские развилки (зафиксированы вопросом):
- состав команд: **только микс-фракции** (любые 3 сети из 18);
- self-play: **frozen-snapshot ротация** (переиспользуем протестированный путь);
- уникальность: **seed + разный рецепт** (без вариаций архитектуры).

Решение:
- 18 faction-locked сетей `MaskedActorCritic` (hidden 128, единый интерфейс
  `train_obs_v3.1`), 6 рецептов (lr/entropy/clip) × 3 фракции, уникальные сиды →
  18 различных genotype_hash. Спецификация — `build_default_population()`.
- Аддитивно расширил `TeamTrainingEnv`: `player_factions` (фракция per-slot,
  следует за сетью при рандомизации позиции) и `opponent_policy_state_ids` (per-
  slot frozen-оппонент из общего pool-чекпоинта). Обратносовместимо (default =
  humans, без state_ids = legacy).
- Новый изолированный нативный тренер `src/training/population.py` +
  `scripts/train_population.py`: per-episode сэмплит микс-фракционную тройку
  обучаемых (team A, рандом позиции) против 3 frozen-снапшотов (team B);
  переиспользует `update_policy`/GAE/`PolicyBot`. Frozen pool обновляется каждые
  N апдейтов. Без отбора: все 18 чекпоинтятся каждый раунд.

Последствия:
- Плюсы: не тронут общий командный тренер (нет регрессий); полное переиспользование
  протестированного RL-ядра; чистая модель «1 сеть = 1 драфт-кандидат» (каждый
  `nets/<id>/latest.pt` грузится `PolicyBot`-ом). 
- Минусы/долги: тренер контролирует только team A (B-side через зеркалирование
  observation), live-both-sides self-play не реализован; throughput-долг
  (~1.9M шагов/час) остаётся; milestone-чекпоинты занимают место.

Проверка: 9 новых тестов (`tests/test_population.py`: uniqueness, faction env,
frozen pool round-trip, scheduling coverage, 1-update smoke) + 49 существующих
зелёные; smoke (1 и multi-worker), resume и full-length sanity (реальные
win/loss) прошли.

## 2026-06-10 — Regionals: ключевые решения

1. **Всё симулируется при создании, включая плей-офф.** Лига и так считается
   заранее; посев плей-офф известен сразу после симуляции лиги, поэтому SF и
   финал играются в том же job. День-гейтинг — чисто презентационный. Следствие:
   персистентные эффекты (Elo, деньги, титулы, h2h) применяются к реестрам в
   момент создания; глобальная страница «Игроки» может «спойлерить» итоги
   текущего турнира — осознанная упрощёнка v1.
2. **Ничья в Bo5-серии плей-офф → проходит команда с более высоким посевом**
   (движок умеет ничьи в играх). Зафиксировано в тестах.
3. **Импакт в Elo ограничен ±20% от базовой дельты** — основа рейтинга всё ещё
   победа/поражение (требование ТЗ); прокси импакта: выживание + core_hp +
   ресурсы относительно своей тройки (per-player урона по ядру в статах нет).
4. **Драфт-порядок: случайный пер-раунд с запретом повторной позиции** — и
   случайно, и сбалансированно, без снейка.
5. **Атрибуты карточек выводятся из реальных eval-данных** (population_balance
   per-net winrate/механики) и снапшотятся в реестр: карточки стабильны даже
   если analysis/ пересоберут; fallback — профиль по рецепту обучения.
6. **LLM опциональна по построению**: инжектируемый клиент (тесты — fake),
   авто-пик при сбое, комментарии только по кнопке и кэшируются. Модель —
   `claude-opus-4-8`, промпты компактные (карточка = 1 строка), structured
   output с enum id для драфта.
