# Просмотр World-вьюера со второго ПК (Tailscale)

Главный ПК держит **весь бекенд** (`viewer/server.py`, тренировки, LLM-запросы, данные миров и
реплеи). Второй ПК открывает вьюер **в своём браузере** и рендерит pixi **нативно** — это полноценный
клиент, а не трансляция экрана.

Почему это работает «из коробки»: вьюер — это статика (HTML/JS/CSS) + JSON-опрос по HTTP
(никаких WebSocket, никаких захардкоженных `localhost`, все запросы — относительные пути). Любой
браузер, который может достучаться до сервера по HTTP, отрендерит всё сам. Проверено: сервер,
поднятый на `--host 0.0.0.0`, отдаёт `world.html` и API по реальному IP, не только по `127.0.0.1`.

**Ограничения, которые мы соблюдаем:** не трогаем порты на домашнем роутере (Tailscale использует
только исходящие соединения + NAT traversal), не используем стрим экрана.

---

## Архитектура

```
   ГЛАВНЫЙ ПК                              ВТОРОЙ ПК (другая сеть)
 ┌──────────────────────────┐           ┌──────────────────────────┐
 │ server.py + тренировки    │           │   браузер (Chrome/Edge)  │
 │ data/world, replays, LLM  │           │   pixi.js рендерит НАТИВНО│
 │ слушает :8001             │           └─────────────┬────────────┘
 └─────────────┬────────────┘                         │ HTTP(S)
               │                                       │
        tailscaled  ◀───── приватный tailnet (100.x.x.x, шифр.) ─────▶  tailscaled
               (только исходящие, роутер не трогаем)
```

---

## Предусловия (один раз, вручную — это твой аккаунт)

1. Установить Tailscale на **оба** ПК: <https://tailscale.com/download>
2. На **обоих** выполнить `tailscale up` и войти **одним аккаунтом** (тогда оба в одном tailnet).
3. Проверить: `tailscale status` показывает оба устройства; `tailscale ip -4` выдаёт `100.x.x.x`.

---

## Способ A — `tailscale serve` (рекомендуется)

Tailscale проксирует твой tailnet (по HTTPS) на локальный `127.0.0.1:8001`. Сервер остаётся приватным
(слушает только loopback), правило брандмауэра **не нужно**, адрес — красивый HTTPS.

Дополнительно один раз: включить HTTPS-сертификаты в админке —
<https://login.tailscale.com/admin/dns> → **HTTPS Certificates** → **Enable**.

На главном ПК:
```powershell
.\start_viewer_remote.ps1
```
Скрипт поднимет сервер на `127.0.0.1:8001` и выполнит `tailscale serve --bg 8001`, затем напечатает
адрес вида:
```
https://<имя-главного-пк>.<твой-tailnet>.ts.net/viewer_pixi/world.html
```
Открой этот адрес в браузере **на втором ПК** (он тоже должен быть в твоём tailnet).

Выключить проксирование: `.\start_viewer_remote.ps1 -Stop`.

Ручной эквивалент (без скрипта):
```powershell
python viewer\server.py --host 127.0.0.1 --port 8001   # окно 1
tailscale serve --bg 8001                              # окно 2
tailscale serve status                                 # покажет ts.net-адрес
```

## Способ B — прямой доступ по Tailscale-IP (запасной)

Сервер слушает **только** Tailscale-интерфейс (`100.x.x.x`) — в домашней LAN он не виден. Не нужен
HTTPS из админки, но может потребоваться правило брандмауэра Windows (локальный фаервол ПК, **не
роутер**).

```powershell
.\start_viewer_remote.ps1 -DirectIp
```
Скрипт попробует добавить правило брандмауэра (нужен запуск от админа) и напечатает:
```
http://100.x.x.x:8001/viewer_pixi/world.html
```
Открой на втором ПК.

Ручной эквивалент:
```powershell
# узнать свой Tailscale IP:
tailscale ip -4
# (от админа, один раз) разрешить порт:
New-NetFirewallRule -DisplayName "SSA World Viewer (Tailscale) 8001" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8001
# поднять сервер только на Tailscale-IP:
python viewer\server.py --host 100.x.x.x --port 8001
```

## Нюанс: pixi.js грузится с CDN

`viewer_pixi/index.html` тянет движок из `https://cdn.jsdelivr.net/...`. Это значит, что **второму ПК
нужен обычный интернет** (для загрузки pixi он ходит на jsdelivr своим каналом, отдельно от tailnet).
Если у второго ПК интернет есть — всё работает. Если он полностью офлайн (только tailnet) — скажи,
**завендорю pixi локально** (положу файл в `viewer_pixi/vendor/` и поправлю importmap), и движок будет
раздаваться с главного ПК.

## Безопасность

- Tailnet **приватный**: доступ только у устройств в твоём аккаунте (ACL по умолчанию — всё своё). Это и
  есть контроль доступа — у самого вьюера аутентификации **нет**.
- Поэтому **не включай `tailscale funnel`** (это публикация в интернет) — нам нужен `serve` (только
  tailnet).
- Если когда-нибудь добавишь чужое устройство в свой tailnet — оно тоже увидит вьюер. Для такого случая
  можно добавить простой токен-доступ к серверу (скажи — сделаю) или ограничить Tailscale ACL.

## Траблшутинг

| Симптом | Причина / решение |
|---|---|
| `tailscale` не найден | Установи и `tailscale up`; перезапусти скрипт. |
| `tailscale serve` ругается на HTTPS | Включи HTTPS Certificates в админке (Способ A) или используй `-DirectIp`. |
| `tailscale serve` не знает команду `--bg` | Старый CLI: `tailscale serve https / proxy 8001`, либо обнови Tailscale. |
| Второй ПК не открывает страницу | Проверь, что он в том же tailnet (`tailscale status` на нём), и что главный ПК онлайн. В режиме `-DirectIp` — что добавлено правило брандмауэра. |
| Страница открылась, но матч/карта не рендерится | У второго ПК нет интернета для pixi-CDN — попроси завендорить pixi локально. |
| Тормозит на тяжёлых реплеях | Реплей-файлы крупные (~2-3 МБ/карта); это сетевая загрузка, не рендер. На медленном канале — норма. |
